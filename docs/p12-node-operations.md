### 渠道证据与环境

- mise 原生 `ls --installed --json core:node` 记录、后端标记字节指纹及真实根目录固定在计划中；
  Homebrew 固定 formula 元数据、已安装版本、修订号、依赖、依赖者和真实 prefix/Cellar。
  执行前重新采集，紧邻变更再次比较；版本、归属或渠道变化均要求重新预览。
  卸载版本承诺来自选中的实际实例，即使 formula 最新版已变化，也不把新版误写成删除目标。
- 所有原生命令清空继承环境，仅显式放入 HOME、系统 PATH 与展示的渠道环境键，
  不继承 NODE_OPTIONS、BASH_ENV 等注入变量。mise 的安装、缓存、状态、下载、shims 与配置查找目录
  都限定在选定 data root，并禁用配置、环境与钩子加载，使用 core 后端且不触发全局激活。
- Homebrew 禁用自动更新、清理、自动移除、隐式安装升级和分析，不提权。
  检查系统、选定 prefix、用户 HOME 的 `brew.env`：任何非空文件都可能覆盖进程环境，
  因而阻止新写计划并显示原因；不忽略或改写用户策略。预览列出依赖与链接影响。
- 管理器证据命令每次最多 10 秒、stdout/stderr 合计 256 KiB；写命令最多 900 秒、512 KiB。
  复用受限进程组运行器，超时、取消和输出超额均终止并回收子进程。
  原始输出只用于有界解析，不写任务日志或 journal；失败显示安全结果说明。
  证据采集的取消等待当前有界命令退出，来源文件系统读取仍保留 P11 的协作取消限制。

参数依据：[mise CLI](https://mise.jdx.dev/cli/)、[ls](https://mise.jdx.dev/cli/ls.html)、

### 变更、清单与结果

[执行器](../src-tauri/src/operation_plan/mod.rs) 采用前置核对、原生命令、来源重扫、结果验证四步。
进入写命令前持有该来源的查询租约，将缓存标记为 `mutationPending` / stale。
普通查询不能与变更交叉提交旧扫描；租约一直保留到重扫结束。即使租约异常丢弃，旧记录也保持过期，
直到完整重扫；完整空结果才能确认来源实例消失，其它来源数据保留。

命令成功、非零退出、超时、取消、恐慌或中途 journal 故障，只要可能已经发生变更，都会尝试只读重扫，
并失效旧管理器缓存。这个清理阶段不继承写任务的取消；它不再运行新的写步骤。
失败、取消或记录故障保留原终态，不能因为重扫发现了文件就改报成功。
重扫不完整时为 `scanIncomplete`，保留未验证状态，不能确认安装或卸载。

- 安装必须在完整新扫描中找到同来源、包、精确目录和实际版本，且健康，才能返回 `installed`。
- 卸载必须确认目标目录消失、来源清单无该实例、原生管理器记录也已消失，才能返回 `uninstalled`。
- 不自动补偿删除已下载内容、重装已卸载版本或清理共享依赖；恢复边界在预览中展示。
- journal 仍只写动作、步骤和安全结果码，新增结果不携带路径、版本、输出、环境值或配置内容。

[界面](../src/components/OperationPlanDialog.tsx) 展示操作影响、原生参数和受控环境键，按钮分别为
“执行安装”“执行卸载”“执行重新验证”。只有完整完成且结果匹配时显示对应成功；
安装完成与项目、终端是否使用该版本分别说明，卸载后提示检查已有引用。
无能力、过期、取消等待、失败和部分完成均有独立反馈，执行后重新读取清单。
长路径和影响在窄窗内换行，关闭入口固定可见，键盘焦点与重复请求保护沿用 PR-04。
