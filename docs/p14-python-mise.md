## 动因

Python 安装不能直接套用 Node 安装参数。mise 可以回退到源码构建，也可以通过默认包文件额外调用 pip。
安装后还会维护版本别名，导致“目录扫描完整”“精确产物健康”“项目实际解析”成为不同结论。
本轮将这些证据放进后端签发计划，先完成一个真实渠道闭环，再继续扩其他渠道。

## 落地

### 原生 mise 适配

新增 [Python mise 写适配](../src-tauri/src/operation_plan/python_mise.rs)，复用原有受控命令环境及有界进程运行器。
Node 写渠道与绑定驱动保持原范围；Python 不通过 Node 的 `WriteSpec` 执行。

只支持 macOS、原生 `core:python`、Python 3.8 起的稳定精确三段版本，且只接受常规预编译 CPython。
范围、别名、预发布、特殊构建和其他后端不获得安装权限。

- 固定 `--no-config --no-env --no-hooks` 和 `core:python@X.Y.Z`，不运行 `mise use`。
- 清空继承环境，固定 HOME、系统 PATH 及本来源的 installs/cache/state/downloads/shims/config 目录。
- 设置 `MISE_PYTHON_COMPILE=0`，并实际读取 `settings get python.compile`，只有确认 `false` 才继续。
- 默认包文件指向本来源受控目录中的不存在路径，并核对 `settings get python.default_packages_file` 的真实结果。
  该路径已有文件、发生重定向或设置不一致时停止，不读取用户的默认包清单来安装额外包。
- 读取并固定原生 `ls --installed --json core:python`、后端收据、来源真实根目录、管理器文件与全局配置指纹。
  预览和执行前均核对；首次安装仅在物理来源目录不存在、无本来源旧缓存且原生记录为空时允许。
- 已有精确目录、安装记录、外部链接、来源不完整或非 core 收据不被覆盖或接管。

设置语义依据：[mise Python](https://mise.jdx.dev/lang/python.html)、
[python.compile](https://mise.jdx.dev/configuration/settings.html#python-compile)、
[默认包文件](https://mise.jdx.dev/configuration/settings.html#python-default-packages-file)。
本机实际能力由命令输出及产物核验决定，不能仅凭文档或可定位的管理器文件开放执行。

显式生成 mise 写计划会读取管理器证据；管理器可能更新自己在受控来源目录内的缓存或状态。
普通清单读取仍不调用管理器、安装器或修复。

### 卸载范围与结果

卸载要求精确版本目录、当前健康实例、原生唯一记录和 `core:python` 收据一致，
可执行文件必须仍在该安装真实目录内。外部版本链接、重定向父目录和其他来源都保持只读。
只调用原生管理器移除这个版本，不删除共享依赖，不改写项目、全局版本请求或虚拟环境。
依赖这个解释器的虚拟环境、项目或终端可能失效，影响在预览中说明。

安装要同时确认：原生命令结果、原生安装记录/收据、精确目录和隔离 CPython 探针。
仅有零退出码、目录或管理器记录都不等于成功。
卸载要同时核对原生记录与物理目标不存在；如果管理器移除整个空来源目录，
可保留清单的过期历史记录，但不能把旧记录当成当前健康实例。

### 任务、取消与来源缓存

复用既有签发身份、120 秒有效期、单次消费、执行前重验、全局任务互斥和最小 journal。
[查询租约](../src-tauri/src/inventory/query.rs) 仅对 Python/mise 开放变更，
写入前使本来源旧证据失效并占住共享读取槽，不影响 Node 缓存和其他 Python 来源。

命令预算为 900 秒、512 KiB 合并输出；证据读取每次 10 秒、256 KiB。
取消、超时或输出超限会终止并回收进程组。无论命令成功、失败或取消，均执行独立的来源重扫；
该清理阶段不继承写任务取消，避免无法报告真实残留。
失败或取消后不自动重装、不自动删除残留；已完成步骤和部分结果分别记录。
原始命令输出、路径、版本、环境值和配置内容不进入持久任务记录。

### 标准别名与界面

真实 mise 会创建 `3`、`3.N`、`latest`，链接目标可以写作 `./X.Y.Z`。
[来源扫描](../src-tauri/src/providers/python.rs) 只把指向同一来源内非链接精确稳定目录的这些标准链接视为已支持布局。
链接记录仍未验证、版本仍未知，不执行链接，不合并来源身份或授予删除权限。
其他别名、外部链接及变体继续报告不完整范围。

mise 还可能更新 shims；已有宽泛版本请求的实际解析可能随别名变化。
计划及完成反馈明确“未改写版本请求，实际解析需另行核对”，不把安装当作项目、终端或 IDE 验证。

共用计划弹窗仅接受后端核定的 Python/mise 原生包安装或卸载执行能力；其他渠道的写能力回复会被拒绝。
Python 实例计划提供重新验证与卸载，安装入口先预览再执行签发 ID。
取消、部分完成和错误产物不会显示安装成功。
目录的 mise 安装/卸载接入账本已同步；共享契约见 [Python mise 样本](../fixtures/operations/python-mise-v1.json)。
