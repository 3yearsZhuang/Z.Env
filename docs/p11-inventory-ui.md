## 动因

PR-01 的统一模型与 PR-02 的四个来源需要接入页面，避免 mise 失败掩盖外部 Node，
或把不同安装目录压成同一个版本。旧页面刷新还会调用托管对账，必须移出读取链。

## 落地

- [查询服务](../src-tauri/src/inventory/query.rs) 通过 `inventory_snapshot` / `inventory_cancel`
  接入 Tauri。同步扫描在后台线程执行，注册租约后才分派，取消可先于线程启动。
  查询不占用原有写操作锁，不生成写任务或历史日志。
- 服务全局最多一个活动扫描；取消接受后仍等待实际工作线程退出才释放槽。租约通过 RAII 处理成功、
  失败、未执行和恐慌退出。取消与缓存提交共用锁，已接受取消的结果不能回写。
- 全量刷新读取四来源；单来源重试保留其它来源的观测和读取时间。只有成功、无错误、完整、
  未截断且新鲜的来源结果可以清除旧记录；失败或不完整扫描保留未再次观测到的旧目录并标过期。
  同目录的新身份替换旧版本，混有旧数据的来源保守标过期，不继续断言旧 alias。
- 缓存仅存进程内；每来源最多 256 条，优先保留新观测，历史截断明确标记不完整。
  请求身份限制为 1–128 个 ASCII 字母、数字、短横线或下划线；最近请求历史 256 条、
  提前取消记录 128 条。无效扫描整批回退，不污染先前缓存。
- [前端查询状态](../src/lib/useInventory.ts) 同时隔离请求身份与激活代次，切页取消当前扫描；
  再次进入先等旧扫描退出，再发起最新查询。失败保留快照并标过期；取消反馈等待真正终结，
  取消失败可重试。明确取消会丢弃排队刷新，不在取消完成后自动重启。
- [Node 清单](../src/components/NodeInventoryPanel.tsx) 分别显示 mise、Homebrew、nvm、PATH 的状态、
  覆盖范围、时间与重试入口；安装实例保留来源、原生包、版本、架构、归属、路径和全部证据。
  同版本不同目录分别展示，文件关联仅作证据链接，键盘可展开并聚焦目标。
  空清单只有在全部相关来源完整成功时才报告未发现，否则明确未知。
- 导航改为“本机工具”；支持列表的 Node 入口直接进入该详情并聚焦标题，无需 mise 可用。
  未迁移工具与写入口保留在“其他运行时与管理操作”折叠区，展开才读取管理列表和体检。
  各旧来源独立发布成功结果，mise 错误不会吞掉 pyenv 等外部结果。
- 页面刷新不再调用 `managedReconcile`。显式“一键修复”保留原后端互斥；修复完成、已有安装/
  卸载/接入/激活/快照重建成功后通知清单刷新。支持列表后台安装完成也通知当前工具页。
  Node 新详情本身仅提供读取、重试、取消与证据浏览。

同步文件系统调用的取消仍是协作检查，单次阻塞调用可能延长取消时间。取消按钮会等待退出，
不会提前表示完成；新查询也不会趁机无限创建线程。来源信任和探针预算沿用 [PR-02](./p11-node-sources.md)。
写操作与读取可能同时进行；清单是带时间的观测，不能作为后续写授权或项目/终端已生效的证明。
