## 落地

[后端计划服务](../src-tauri/src/operation_plan/mod.rs) 提供 `operation_plan` 和 `operation_execute`。
预览请求只包含当前快照身份及结构化意图；执行请求只包含后端保存的 `planId`。
前端不能提交自定义程序、argv、cwd 或配置内容。完整计划与目标证据仅存在进程内，重启后必须重新预览。
Rust/TS 共用 [契约夹具](../fixtures/operations/contract-v1.json)。

### 计划与执行保护

- 每份计划固定清单提交代次与请求身份；来源刷新后，即使仍显示相同实例，旧计划也须重新预览。
  活动扫描期间不签发或执行计划。计划缓存最多 64 份，默认有效期 120 秒，执行单次消费；
  同时检查墙钟和单调时钟，过期、被替换或已消费的身份均拒绝执行。
- [证据守卫](../src-tauri/src/operation_plan/guards.rs) 固定来源根目录、PATH、平台、扫描预算、
  目标程序和管理器文件身份及真实路径。配置最多读取 1 MiB，使用 SHA-256 原文字节指纹；
  检查内容、存在状态与真实目标，包括不存在文件的父目录软链接重定向。
  拒绝断链、特殊文件或无法完整读取的证据，读取不创建配置。
- 复用 `operations.rs` 全局单写互斥，在锁内重验上下文、配置、清单与文件。
  步骤内再次核对来源和精确实例；供后续接入的变更步骤会紧邻调用重新核对前置条件。
  新计划的执行器本身继续拒绝命令写执行，不能绕过未开放能力。
- 已验证实例经原来源重新读取，最终必须仍是同一安装身份、健康状态和归属，才能报告验证通过。
  只确认原文件与版本，不代表项目约束满足或用户终端已经生效。
- 取消先记录请求，等实际步骤与来源扫描退出；线程登记前到达的取消也会命中尚未消费的计划。
  来源取消继续受 P11 同步文件系统的协作边界限制。读取过程中不提前释放全局写槽。
- 步骤状态区分待执行、进行中、完成、失败、跳过；任务区分完成、部分完成、失败、取消和中断。
  变更步骤返回错误也可能已有副作用，内核保守保留部分完成结果；该路径目前只由注入式测试验证。

直接依赖的 `sha2 0.10.9` 已存在原 Cargo.lock，本轮只增加应用依赖边，不升级或重新解析依赖版本。
目标文件身份与版本重探针不能锁住外部管理器；实际写渠道开放前仍须在 PR-05/06 补齐相应前置条件、影响与补偿验证。

### 最小 journal 与页面

[Journal](../src-tauri/src/operation_plan/journal.rs) 使用 `~/.zenv/operations-v1.json`，最多 64 条、
256 KiB，单份记录最多 8 步。只保存后端任务 ID、动作枚举、步骤和安全结果码；
不写路径、版本、原始命令、输出、环境值、配置内容或配置指纹。完整配置备份仍由既有配置服务负责。

启动仅恢复已经存在的 journal；全新的只读会话不创建 journal 或锁文件。
第一次明确执行时先准备记录并原子写入，再进入步骤；各次状态更新也须成功落盘才继续。
同目录临时文件替换、文件同步、目录同步和 Unix 进程锁保护记录，文件权限为 0600。
写前比对上次原文字节，检测到外部编辑时保留外部内容并停止后续步骤。
持锁的其它应用实例、损坏/过大/未来格式文件、软链接或 IO 故障均阻止新执行，不覆盖损坏原文。
新执行支持 macOS；Windows 未开放此 journal 执行路径，旧任务行为继续保留。

重启将 running 记录转换为 interrupted：保留完成步骤，正在执行的步骤标未完成，后续步骤跳过，
**不自动重放安装**。任务面板显示中断说明和逐步状态；原有内存任务不会因此获得跨重启恢复能力。
中途 journal 更新失败会阻止下一步并标记任务中断，重启按最后可靠记录恢复。
新操作会停止执行，需先排除记录问题；旧入口保留。

[计划对话框](../src/components/OperationPlanDialog.tsx) 从 Node 清单按需加载：
顶部可预览安装，展开实例后可预览重新验证、卸载或绑定能力。界面展示目标、版本承诺、配置影响、
权限、恢复边界、有效期与步骤。明确点击后才请求预览或执行；取消、失败和过期均有反馈。
迟到预览或取消错误不覆盖新状态，执行后通知清单重读；关闭对话框后任务继续由全局面板管理。
键盘焦点圈定，Esc 关闭回到原入口，长路径换行且关闭入口固定可见。
