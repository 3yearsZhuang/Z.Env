# P14 / 43 — 项目配方只读预览（工作包 10）

日期：2026-11-04（Asia/Shanghai），分支 `main`。
状态：**只读配方预览完成；执行与失败步骤重试待继续。**
本切片不写项目文件、不安装工具、不消费计划。

## 动因

预设库与项目声明各自可用，但用户看不到“这套预设装到当前项目会发生什么”。配方预览把预设工具、
项目声明、当前清单与各渠道能力汇总为逐项处置，先回答“能复用/需安装/冲突/不支持”，
再决定是否进入各渠道的独立写计划。

## 落地

- 新增 [recipe.rs](../src-tauri/src/recipe.rs)：纯只读汇总，输入预设工具、清单、可选 Python 项目报告，
  输出 `RecipeReport`。
- 逐项处置：
  - `reuse`：清单里有该精确版本的健康实例（标注来源与安装 ID）；
  - `install`：可生成可执行的 Python mise 精确安装计划（`planReady`）；
  - `conflict`：Python 项目声明与候选冲突；
  - `unsupported`：工具或渠道未接入；
  - `unknown`：版本是范围/别名，只读无法判断。
- 版本只接受精确 3 段（Python `3.x.y`、Node `x.y.z`）；范围与别名明确标 `unknown`，不猜测。
- `executable` 仅在所有项都可复用或具备可执行计划时为 true。
- 新增 `recipe_preview` 命令；工具数上限 64，项目报告可选并沿用现有租约读取。
- 前端在“装到整机”预设弹窗内显示只读配方检查计数；检查失败只降级为“未检查”，不阻塞原有安装。

## 边界与后续

- 虚拟环境初始化、项目级安装、旧预设执行路径尚未并入配方。
