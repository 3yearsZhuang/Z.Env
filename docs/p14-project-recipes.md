## 动因

原预览对所有工具使用默认 Node 清单，Python-only 与混合配方因此无法正确绑定证据。
健康实例判断还早于项目要求核对，临时安装预览会占用真实计划缓存。修正使预览结果可用作只读判断。

## 当前行为

- [recipe.rs](../src-tauri/src/recipe.rs) 与 `recipe_preview` 共用生产入口：一次锁内捕获相关工具的
  独立清单，锁外读取项目声明及既有渠道门禁，返回前重验 generation/request ID。
  活动扫描、清单被刷新或原本缺失的清单新出现时拒绝旧报告，不自动重扫。
- `RecipeReport` schema 2 的 `snapshotBindings` 按工具返回 request ID 和字符串 generation；
  缺失清单明确为 null。旧 `snapshotRequestId` 仅单工具且有清单时有值，混合配方为 null。
  原 `recipePreview(tools)` 仍发送 `{ tools, project: null }`，可选第二参数传入 Python 项目请求。
- 每项先核对本工具预期来源集合及完整、新鲜覆盖，再核对精确版本、Python 项目要求、已有候选和安装能力。
  缺失/空/失败/过期/部分来源，以及版本范围或别名保持 `unknown`，不依据未知状态推断可安装。
- Python 声明沿用已有解析器，对全部已读取要求求交，并检查请求版本本身。
  冲突或请求版本不满足要求为 `conflict`，未知声明为 `unknown`；均在复用和渠道探测前停止。
  返回前再次比较项目目录及文件指纹，文件新增、删除或改写后拒绝旧报告。
- `reuse` 仅表示已有精确、健康、新鲜的管理器来源候选，无需重复安装；PATH 观测不作为复用目标。
  合法 `Observed` 候选保留，不代表项目已绑定、终端/IDE 环境生效或已有虚拟环境可用。
- Node/Python 精确安装均调用已有 mise 计划门禁；只有渠道允许执行才给出 `install` / `planReady`。
  门禁失败、缺管理器或执行未开放时保持 `unknown`，报告不携带计划 ID。
  全局配置路径与独立计划入口一致，沿用自定义 mise/XDG 配置位置；不固定假设默认路径。
- 安装能力使用隔离临时预览会话，继承真实服务的 journal 故障状态，不恢复/写入 journal，
  不改变真实计划缓存或淘汰用户已打开的计划。
  返回前再次核对真实 journal 状态，期间故障后拒绝旧安装能力结论。
- 配方 `executable` 始终为 false，包括空配方。工具数上限 64，显式项目 ID 与路径预算保持校验。
  前端预设弹窗显示处置计数；检查失败仍允许用户进入已有整机安装流程。
