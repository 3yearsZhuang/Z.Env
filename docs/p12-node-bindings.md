## 动因

目录被发现、进入 mise 注册、配置选中某版本和用户终端实际运行该版本，是四个不同结果。
绑定需要先展示准确的目标、链接和配置差异；失败或取消后的恢复也要有独立结果。
解除绑定只能撤回本绑定拥有的资源，不能借助卸载命令删除原管理器的安装目录。

## 落地

[绑定服务](../src-tauri/src/operation_plan/bindings/mod.rs) 接入现有短期单次计划、写互斥、
配置和目标证据守卫、查询租约及 journal。请求描述方式、范围与项目位置，执行仍只传 `planId`。
前端不提供任意命令、补丁或回滚内容。新的 `operation_bindings` 只读取绑定摘要；
未打开绑定管理时不会读取或自动处理绑定，更不会重放中断的写步骤。

### 开放的方式与范围

| 方式 | 适用来源 | 作用范围 | 写入与验证 |
| --- | --- | --- | --- |
| 直连 | 原生 mise 或 nvm 的健康精确 Node 目录 | 仅注册 / 注册并选为全局 / 注册并选为项目版本 | 原生 mise 安装直接复用；nvm 仅在空位置建立精确版本注册链接。核对原生注册记录及受控进程的版本、真实文件路径 |
| 托管 | 已确认 core 归属的健康 Homebrew 实例 | 同上 | `~/.zenv/managed/node/精确版本 → 原目录`，再由 mise 精确版本链接指向农场；验证两层链接、原生注册及受控运行 |
| 项目 PATH | 支持的健康 mise / nvm / Homebrew 精确实例 | 仅项目 | 将该实例原始 `bin` 路径放在项目 `env._.path` 首位；不建立 mise 链接、不修改 tools 中其它工具，验证受控 PATH 解析的实际 Node |
| 解除绑定 | 本服务签发的已确认或待确认收据 | 收据中的原范围 | 恢复该绑定之前的配置，移除本绑定创建的链接；保留所有原安装。来源已经失效时也能显式解除，不再执行失效来源文件 |

只支持 macOS Node 试点及精确版本目录，版本别名、未知 PATH 文件、外部链接再次转接、
复杂 Node 配置、动态 PATH 表达式和混合 Node 后端声明保持手动处理。
项目 PATH 遇到现有 Node tools 声明时拒绝执行，避免 PATH 与工具选择的优先级冲突。
项目目录会绑定到实际的 `mise.toml` / `.mise.toml`；隐藏文件存在时不另建普通文件，
旧 `.tool-versions` 须先在项目编辑器显式迁移。全局配置不能误作独立项目选择。

同版本的独立安装、其它链接及旧 managed 清单条目不能被覆盖；发现旧接入时先要求在旧入口处理。
同一精确版本的 mise 绑定暂不复用多份新收据，同一配置文件只允许一份新绑定；
项目 PATH 可用于不同项目。后续扩展多作用范围复用前，需要显式引用计数和冲突模型。
本轮没有将目录观测升级为所有权，也没有把绑定登记写入旧 managed manifest。

### 配置差异、记录与恢复

[资源比较层](../src-tauri/src/operation_plan/bindings/resources.rs) 固定每个路径的真实父目录、
原文件原文或链接目标。应用前比较原状态，写入后核对结果；配置走既有
[配置服务](../src-tauri/src/config.rs) 的串行、备份和原子替换路径。新配置撤回前也保留 `.zenv-backup`。
正常配置软链接沿原目标写入；预览后重定向、外部改动或类型变化会阻止覆盖。
链接创建复用 [managed 原语](../src-tauri/src/managed.rs)，只接受不存在的位置，绝不删除普通安装目录。

绑定摘要与完整恢复信息在 `~/.zenv/bindings-v1.json`：最多 32 份、总计 1 MiB。
**该文件包含完整配置恢复原文**，因此独立于最小 journal，文件权限仅限当前用户；
已有文件若向组或其他用户开放则停止新操作。配置内容不回传摘要，也不写任务日志或 journal。
记录损坏、未来格式、软链接或超出预算时停止，不把它当空记录覆盖。

执行顺序：先原子写入 `pending` 收据，再按计划修改链接与配置，最后完成受控验证后改为 `bound`。
这样即使进程在中途退出，仍有明确的待确认资源；重启不重放绑定，用户从“管理 Node 绑定”显式预览解除。
收据内容再次校验合法的来源布局、路径范围、精确链接目标和配置变换，不能用被改写的恢复路径操作无关文件。

失败或取消后，执行器追加 `compensate` 步骤，补偿不继承取消。
只恢复仍等于本次写入结果的资源；已经恢复的资源跳过，外部改动不会被覆盖。
如果某个配置发生冲突，可独立撤回其它仍可确认的链接，同时保留待确认收据与备份。
补偿结果区分 `completed` / `conflict` / `failed`，原任务仍保留失败、取消或中断状态。
中途 journal 失败也要尝试补偿，并保留外部 journal 内容；重扫在补偿后再次运行以更新缓存。
补偿后的成功并不等于原绑定成功。

配置和链接按资源逐项比较、修改和补偿，不构成跨文件事务；收据与备份提供恢复依据。
收据冲突时需要先核对外部修改，不能点击重试强行覆盖。

### 结果验证的准确范围

- 直连/托管必须由 `mise ls --installed --json core:node` 返回唯一目标注册，且实际指向选中实例。
  受控 `mise exec core:node@精确版本 -- node -p ...` 还须返回正确的版本与真实 `process.execPath`。
- 验证明确禁用配置、环境和钩子加载，并设置 `MISE_AUTO_INSTALL=0`、`MISE_EXEC_AUTO_INSTALL=0`、
  `MISE_NOT_FOUND_AUTO_INSTALL=0`；不会为了验证自动下载缺失版本。
  命令沿用有界运行器，受控探针最多 10 秒、64 KiB，取消终止并回收进程组。
- 全局/项目配置先核对与签发差异对应的完整原文，再将计划中的精确 Node 选择或 PATH 投影到受控进程。
  **不会加载真实项目的任意环境表达式或钩子**。这证明指定选择可解析到该实例，
  不等于用户终端、IDE 或项目的全部隐式配置已经生效；实际声明优先级和环境冲突留给 P13。
- 解除只核对本收据资源已恢复、链接不再属于该绑定、记录已移除；
  不自动选用替代版本，不跨版本重连，不调用 `mise uninstall` 或 Homebrew 卸载。

原生命令语义核对：[mise link](https://mise.jdx.dev/cli/link.html)、
[mise exec](https://mise.jdx.dev/cli/exec.html)、[自动安装设置](https://mise.jdx.dev/configuration/settings.html#auto_install)。
本服务直接创建已审阅的链接，避免把原生命令的其它副作用混入链接补偿。

[界面](../src/components/OperationPlanDialog.tsx) 可选择方式与范围，展示字段修改前后值、
文件位置、精确链接和恢复边界。Node 清单有独立绑定管理入口，来源已不可见也能查看中断收据。
执行按钮与反馈区分绑定和解除；任务面板独立显示补偿结果。
更换意图丢弃迟到预览；收据重读不会吞掉解除成功反馈。
