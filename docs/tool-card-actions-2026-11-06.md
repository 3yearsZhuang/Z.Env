# 50：Node/Python 卡片连接实例与操作计划

日期：2026-11-06；验收更新至 2026-11-07（Asia/Shanghai）；基线 `1e4859d`（第 48、49 项已合并）。

## 动因

软件支持卡片的 Node 已能进入独立清单，Python 仍使用旧运行时弹窗。集成渠道上的安装按钮也仍调用旧系统安装路径，目录能力与实际入口不一致。本切片把两种工具的查看和计划入口连接到已有清单与后端签发流程。

## 行为与约束

- Node/Python 主按钮都进入对应本机清单。旧 mise 列表读取失败不阻止独立清单；其他工具继续使用已有兼容入口。
- Node/Python 目录正在读取、读取失败，或工具/渠道能力缺失时禁用旧安装。只有成功目录明确标记 `notIntegrated` / `unsupported` 的来源保留兼容入口；集成渠道缺少计划回调时也不回退写入。
- 已接入的安装渠道使用“预览计划”，保留工具、provider 与原生 package ID。Homebrew formula、pyenv/uv 来源身份不被默认为 mise；复制命令不触发导航或写入。
- `EnvironmentView` 保存一份带唯一 ID 的导航意图和原触发按钮，传给对应清单。请求回执按 ID 清理，迟到回调不能清空新工具请求。
- 意图需要一轮成功清单读取才能打开计划。`useInventory.ready` 绑定当前激活周期，旧缓存、读取失败、取消和等待状态不能提前消费。失败后保留意图供重试，也可独立取消计划请求。
- 清单与兼容区首次访问才加载，访问后保留会话。Node/Python 共享弹窗所有权，安装、验证、绑定和解绑入口统一申请；已有计划和任务不被新导航覆盖，最新导航请求在关闭计划后重新读取并处理。
- 计划弹窗使用现有 v2 API，检查工具、快照、动作、provider、原生包、类型、平台及实例身份，执行仍只提交后端签发的 plan ID。目录的 integrated 不提升 `canExecute`。
- Python 说明与现有四渠道安装/卸载和 mise 绑定/项目要求核对范围一致；渠道未通过门禁时显示原因。
- 关闭弹窗归还原按钮焦点；原按钮已隐藏或移除时回对应可见的运行时切换按钮。
