## 收敛后的规划主线

用户目标已从 mise 图形界面转为本机工具管理中心。mise 应成为可选 provider，统一流程围绕“本机有什么、由谁管理、哪个作用域会使用它、执行什么变更、如何验证结果”组织。

当前实现已有多来源扫描、系统包安装和任务管理基础。重构优先解决统一工具与安装实例身份、provider 能力、上下文与状态口径，再迁移操作和页面。相同版本的不同安装实例不能按名称合并；已安装、满足项目要求和实际生效必须分别表达；版本目录可列举某版本不代表安装渠道能安装它。

阶段顺序为：P11 多来源只读清单 → P12 统一操作 → P13 项目需求与解析 → P14 工具与配方 → P15 诊断及服务缓存 → P16 快照与旧入口收口。首个纵向范围限定 macOS + Node.js，读取 mise、nvm、Homebrew 和 PATH 候选；读取不能触发托管对账、修复、安装或配置写入。来源失败保留部分结果并明确未知状态，无 mise 仍能查看外部工具。

前两阶段拟拆六个 PR：①身份、证据、状态契约与纯合并器；②只读 Node adapters 与受限探针；③inventory API 与界面；④能力判断与可审阅操作计划；⑤provider 安装/卸载与验证；⑥实例绑定、解除绑定及回滚。完整范围、依赖和验收场景见 [重构方案](../refactor-plan.md)。
