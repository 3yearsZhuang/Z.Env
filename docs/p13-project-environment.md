## 动因

项目声明 Node 22，机器上存在 Node 22，并不能证明项目或应用实际运行 Node 22。
此前项目发现依赖 mise 工具名判断缺失，既不能核对版本，也会漏掉其他来源。
本轮把声明、候选、配置选择和上下文解析分别建模；任何一项未知都保留原因，不汇总成笼统的“环境就绪”。

## 落地

### 独立状态与范围

[后端](../src-tauri/src/project_environment/mod.rs) 和 [前端契约](../src/api/projectEnvironment.ts)
共享 [JSON 样本](../fixtures/project-environment/contract-v1.json)，报告包含以下互不替代的证据：

| 维度 | 本轮行为 |
| --- | --- |
| 声明要求 | 读取项目 `mise.toml`、`.mise.toml`、`.nvmrc`、`.node-version`、`.tool-versions` 及 `package.json engines.node`，求受支持版本范围的交集；交集为空才判冲突，不能由“未安装”推断冲突 |
| 安装候选 | 复用当前 inventory，保留来源与实例身份；要求匹配与来源健康分别展示。PATH 观测不升级为可信安装。过期、读取不完整、未通过健康探测的来源不能作为可用实例 |
| 配置选择 | 简单单一 `tools.node` / `tools.core:node` 数字请求，或不与 Node tools 并存的静态绝对 `env._.path` 数组；全局配置仅作后备选择，不变成项目要求 |
| 项目受控上下文 | 显式点击后验证上述选择的受限 Node 投影，返回真实版本、`process.execPath` 和来源身份；项目声明满足与配置选择满足分别判断 |
| 应用继承 PATH | 按捕获的应用 PATH 顺序定位第一个可执行 Node，在清空注入环境的进程中核对。首项未知时不执行，也不跳过它选择后面的已知版本 |
| 用户终端与 IDE | 始终独立标为未知；本轮没有读取对应进程环境，也不以应用 PATH 或受控投影替代 |

需求状态为未声明、支持、冲突或未知。稳定数字版本支持精确、主/次版本、通配、`^`、`~`、
紧邻数字的比较符组合和 `||`；不支持 prerelease/build、别名、hyphen range、逗号或分离的比较符等语法。
例如 `>=22 <23` 可解析，`>= 22` 暂保留未知。该子集以
[npm node-semver](https://github.com/npm/node-semver#ranges) 为语义参照，
[独立 oracle 样本](../fixtures/project-environment/node-ranges-v1.json) 固定了 31 个范围 × 20 个版本的 620 个比较结果；
没有新增 npm 或 Cargo 依赖。区间求交会合并重叠与相邻区间，重复 OR 声明不会造成组合数量指数增长；空版本范围也可独立识别。

复杂 Node 值、多后端、多份项目配置、祖先配置、include/extends/settings、local/平台变体及 lockfile
均不假定优先级；保留配置选择未知。`.nvmrc` 等声明本身不等于 mise 已配置对应选择。
全局与祖先关系按 [mise 配置语义](https://mise.jdx.dev/configuration.html) 设定保守边界，
当前没有实现完整的 mise 隐式解析器。其他工具、Windows/Linux 及复杂继承不属于本轮完成范围。

### 读取与执行边界

普通配置每文件最多 128 KiB，合计 1 MiB、最多 96 条读取证据、64 条 Node 声明，超出保留未知；祖先深度 16，目录变体检查最多 256 项。
拒绝 FIFO 等特殊文件，读取后比较实际路径、文件身份、时间和 SHA-256。
探测前后重新检查声明及项目目录身份/成员变化：配置原文变化、软链接重定向、新增变体都使报告失效，
保留外部修改；目录不可完整枚举时不确认配置选择。
这些守卫提供有界的前后核对，不构成文件系统事务或后台持续监控。

受控命令清空继承环境，显式禁用配置、环境表达式和钩子，
`MISE_AUTO_INSTALL`、`MISE_EXEC_AUTO_INSTALL`、`MISE_NOT_FOUND_AUTO_INSTALL` 全部为 `0`。
只运行固定 Node 表达式，最多 3 秒、64 KiB；取消终止并回收进程组。
数字 mise 请求还要求已有新鲜健康的对应注册，未注册时提示显式绑定，不自动下载。
静态项目 PATH 只检查声明路径投影，不补入任意终端环境。

新增 `project_environment` IPC 只接受请求身份、清单身份、项目路径及是否探测，不接受 argv 或补丁。
它与 inventory / 写任务使用同一后端租约；读报告不会重新提交清单缓存。
前端 [共享读取队列](../src/api/inventoryRead.ts) 等待旧线程退出后分派下一读取，取消信号不排队。
切页、换项目、清单更新、失败和接受取消后的迟到成功，均不能恢复旧报告的有效状态。
报告与原文只在内存使用；没有新增持久 journal 或环境值副本。报告包含本地路径和文件摘要，供当前用户核对。

### 项目页面与操作

[项目环境面板](../src/components/ProjectEnvironmentPanel.tsx) 随已载入项目按需加载。
首次只读取声明和候选；“验证受控上下文”显式启动进程探测。
冲突、未知、部分来源、草稿及旧结果各自展示，已安装候选不会隐藏实际版本不匹配。

健康且满足声明的实例可以预览绑定，复用既有 `OperationPlanDialog`，预选当前项目作用域；
来源、精确目标、配置差异、执行及补偿仍由 P12 计划服务处理。
安装同样只打开现有计划入口，必须显式选择渠道和版本；不会从声明自动执行安装。
操作结束后编辑器保留草稿，标记配置可能已变，并阻止继续保存，直到重新读取磁盘内容。

[项目发现](../src-tauri/src/discover.rs) 已移除 mise 名称清单调用。
发现徽标仅表示配置是否存在；工具名只作为指纹提示。旧 `missingTools` 字段为兼容保留为空，
不能再把目录扫描误当版本满足或缺失结论。
