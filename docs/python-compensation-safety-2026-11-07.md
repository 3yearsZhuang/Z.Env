# Python 绑定补偿：外部修改与取消后的清理

日期：2026-11-07（Asia/Shanghai）；基线 `35688bd`。
动因：第 51 项配方执行设计审查发现既有 Python 绑定的两处恢复边界缺口，先修正底座再接入配方。

## 问题

绑定后的验证失败会触发自动补偿。原实现只检查 Python 字段仍等于本次写入值，随后恢复整个旧配置文件。
如果外部程序在此期间仅改写 `tools.node`、其他字段或注释，Python 字段不变，补偿会覆盖这些外部修改。
收据删除失败也会被忽略，可能报告补偿完成，却留下未处理的绑定记录。

Python 绑定变更未取得清单 mutation lease。写入后取消时，正常刷新与补偿后的终态刷新仍受父取消影响，
可能已恢复配置，却没有完成用于确认实际残留的清理扫描。

## 修正要求

- 恢复整份配置前核对完整写后内容；任意外部修改均保留并报告冲突，不依据 Python 字段相等推断整份文件归属。
- 正常恢复和已恢复后的幂等路径都核对收据清理结果；清理失败继续报告失败，不给出补偿完成结论。
- 绑定与补偿变更取得对应 Python/provider 的阶段 lease 并标记清单失效，结束后重新读取实际来源。
- 写后和补偿清理扫描使用独立取消范围；父任务取消后停止后续变更，但必要清理仍完成。
- 共享执行器保留补偿的实际错误分类；收据 I/O 失败为补偿失败，外部修改仍为补偿冲突，返回错误和持久记录保持一致。
- 纯验证扫描保留正常取消行为。界面 Close/Escape 和后台任务流程保持原有交互。
